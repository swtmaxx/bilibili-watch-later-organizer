# 面向普通用户的术语与交互规范

状态：已确认，待后续开发任务实施。

本文面向项目开发者和代码代理，用于统一插件公开发布后的产品术语、统计口径、功能边界与关键交互。修改界面文案、首次引导、README、状态提示、分类流程或视频卡片前，应先阅读本文。

## 1. 基本原则

- 主界面优先使用普通用户可以直接理解的中文，不直接暴露 `keyword`、`LLM`、job、cache 等内部术语。
- 用户看到的是“分类阶段”和“下一步可以做什么”，内部代码仍可继续使用 `keyword`、`llm`、`manual` 等稳定字段，避免无必要的数据迁移。
- “分类目录”和“视频分类”是两个不同对象，所有按钮、提示和更新说明都必须明确区分。
- 手动确认的视频分类具有最高优先级，任何自动分类、导入、重置或修复流程都不得覆盖。
- 后台同步和详情补充属于运行状态，不属于分类统计。

## 2. 分类阶段与分类方式

界面对分类结果采用“两种阶段、三种方式”的表达。


| 内部来源  | 用户名称 | 分类阶段 | 用户含义                                                 |
| --------- | -------- | -------- | -------------------------------------------------------- |
| `keyword` | 初步分类 | 粗分类   | 插件根据标题、分区等信息快速自动判断，可能需要进一步确认 |
| `llm`     | AI 分类  | 细分类   | AI 阅读视频信息后进行更准确的分类                        |
| `manual`  | 手动确认 | 细分类   | 用户亲自调整并保存，自动流程不得覆盖                     |

统一优先级：**手动确认 ＞ AI 分类 ＞ 初步分类**。

视频卡片来源徽章只显示：

- 初步分类
- 手动确认

AI 分类仍用于右侧统计和分类状态判断，但不在视频卡片上显示来源徽章。

首次引导或帮助说明使用：

- **初步分类**：插件会先自动整理，速度快，但可能不够准确。
- **AI 分类**：使用 AI 进一步判断视频内容。
- **手动确认**：你亲自确认的分类具有最高优先级，不会被自动修改。

## 3. 特殊分类与筛选

### 待精细分类

左侧原“未分类 / 待更新”统一改为 **待精细分类**。它是工作状态筛选，不是分类目录中的一个分类。

应纳入该筛选的情况：

- 只有初步分类；
- 没有有效分类；
- 分类结果过旧；
- 分类结果不确定或低置信度。

用户可以选择 AI 分类或手动调整，因此不得写成“待 LLM”或“待手动”。

### 视频时长筛选

视频列表可以按常用时长区间或自定义范围筛选。没有有效时长的视频统一称为 **时长未知**，它不归入任何有效时长区间。

### 视频视图

视频列表支持 **卡片视图** 和 **列表视图**。视图切换只改变视频的排列和信息密度，不改变筛选、排序、分类或批量操作；用户的选择会在下次打开整理助手时保留。

### 暂未归类

分类目录中原“其他 / 待整理”改为 **其他 / 暂未归类**。它表示现有信息不足，暂时无法确定更合适的目录位置，是正常的兜底分类。

内部 id 可继续保持 `other.todo`，无需仅为文案改名迁移历史数据。

### 分类异常

“未分类”不作为常驻入口或统计项。真正没有任何有效分类的情况统一称为 **分类异常**，只在数量大于 0 或确实需要用户处理时显示。

## 4. 右侧统计口径

右侧常驻统计只保留四项：

1. **全部视频**
2. **待精细分类**
3. **AI 已分类**
4. **手动确认**

后三项必须互斥，并且数量之和应等于“全部视频”：

- 待精细分类：初步分类、无有效分类、结果过旧或结果不确定；
- AI 已分类：当前有效、无需重新处理的 AI 分类；
- 手动确认：用户手动保存的分类。

删除原统计中的“待 LLM”“未分类”“任务”。后台详情 job 不再作为常驻数字显示，改为按需出现的动态状态，例如：

- 正在同步稍后再看……
- 正在补充 12 个视频的信息……
- 同步完成 · 共 836 个视频
- 上次同步：2 分钟前

## 5. 分类目录与视频分类的固定边界

### 分类目录

分类目录表示“有哪些分类，以及它们之间的层级关系”。统一使用以下表达：

- 编辑分类目录
- 让 AI 生成分类目录
- 导入并替换分类目录
- 恢复默认分类目录

有子分类的一级分类可以通过右侧的展开/折叠按钮隐藏或显示全部后代分类。分类目录默认全部展开，折叠状态按分类 ID 保留；折叠只影响目录显示，不改变视频分类结果、筛选统计或分类层级。二级及更深层级不提供单独的折叠按钮。

避免使用含义不明确的“更新分类列表”。相关说明应明确写出：

> 分类目录决定可以使用哪些分类；生成目录本身不是在给每个视频分类。

让 AI 生成分类目录时，插件会从当前稍后再看视频中抽取样本。视频样本只包含标题、UP 主、B站分区、标签、简介、分P标题和时长；当前分类目录会作为结构参考。这个过程不发送播放量、互动统计、观看进度或本地分类记录，也不会因此给视频分类。

### 视频分类

视频分类表示“把具体视频放入分类目录中的位置”。统一使用以下表达：

- AI 批量视频分类
- 手动调整视频分类
- 重新分类这些视频
- 批量调整视频分类

AI 批量视频分类会参考视频标题、UP 主、分区、标签、简介、分P标题、时长和分类目录关键词；详情不足时会先排队补充。AI 返回的结果只会应用于当前批次，手动确认的视频不会被自动修改。

### 已确认的功能名称


| 当前名称           | 确认采用的名称                      |
| ------------------ | ----------------------------------- |
| 分类管理           | **编辑分类目录**                    |
| 自动 LLM 分类 | **AI (API) 批量视频分类** |
| 手动修正      | **手动调整视频分类**      |

功能名称中的括号和 `API` 按以上文本保留，以便明确表示插件自动调用 API。

右侧界面使用 **AI 批量视频分类** 卡片提供 API 分类入口。分类目录生成与 API 视频分类共用 **设置** 中可单独折叠的 **API 设置**；相关入口按钮统一使用 **设置API**。

**自动 API 视频分类** 作为设置中的独立折叠项，可选择关闭、每天、每周，或在“待精细分类”达到用户指定数量时自动触发。自动流程仍不得覆盖手动确认。

## 6. 视频卡片操作

视频卡片采用以下交互：

- 删除“普通打开”文字按钮；
- 点击视频封面，直接打开普通 B站视频页面；
- “稍后播放”改名为 **稍后合集中打开**，用于进入 B站稍后再看播放上下文；
- “移出稍后”改为单独的删除图标按钮；
- 删除图标必须具有明确的 `title` 和 `aria-label`，推荐使用“移出稍后再看”；
- 删除仍是破坏性操作，保留确认步骤，不能因改成图标而静默删除；
- 视频标题是否同时打开普通视频页可在实施时根据可访问性决定，但不得与卡片选择、文字选择或手动分类操作冲突。

实现时继续遵守已有交互约束：不得引入滚动跳动、文本选择丢失、输入法异常或批量选择失效。

## 7. 收藏夹批量操作

批量管理模式提供独立的 **新建收藏夹** 面板。它复用当前已选择的视频，不改变视频分类或稍后再看列表。

- 每次提交都会新建一个 B站收藏夹，名称由用户输入，默认设置为私密。
- 选中视频会使用其 `aid` 加入新收藏夹；缺少 `aid` 时插件会先补充视频详情。
- 重复选择、缺少有效视频编号或接口失败的视频不会中断整个操作，完成后统一显示成功、跳过和失败数量。
- 该操作只调用 B站收藏接口，不调用 AI，也不会把标题、简介、标签或分类记录发送给 AI 服务。
- 当前浏览器不必正打开 B站页面，但必须保持 B站登录状态；登录或 CSRF 失效时会提示重新登录。

批量管理还提供 **批量移出稍后再看**。确认后插件会逐个请求 B站接口从稍后再看中移出选中视频；如果 B站拒绝扩展来源，插件会在后台临时使用 B站页面上下文重试，不要求用户手动打开页面，但需要保持 B站登录状态。本地视频记录、分类结果和手动确认会保留。单个项目失败不会中断其他项目，失败视频会继续保留在选择中以便重试。

## 8. 产品标题

左上角固定文案采用：

> **稍后再看整理助手**
> 自动归类，快速找到想看的视频

删除“缓存优先显示，后台增量同步”这类技术实现描述。同步情况使用独立的动态状态展示，不占用产品副标题。

## 9. 公开文案替换表


| 避免使用        | 改用                                     |
| --------------- | ---------------------------------------- |
| 稍后再看分类库  | 稍后再看整理助手                         |
| keyword         | 初步分类                                 |
| LLM             | AI；仅高级技术说明可写“AI 模型（LLM）” |
| keyword 判定    | 自动初步分类                             |
| 手动修正        | 手动调整视频分类 / 手动确认              |
| 待 LLM          | 待精细分类                               |
| 未分类 / 待更新 | 待精细分类                               |
| 低置信度        | 结果不确定                               |
| 待更新          | 建议重新分类                             |
| 待整理          | 暂未归类                                 |
| 任务            | 动态显示具体同步或详情补充状态           |
| 更新分类列表    | 生成、替换或编辑分类目录                 |
| 更新视频分类    | 对视频进行分类 / 重新分类视频            |
| 稍后播放        | 稍后合集中打开                           |
| 普通打开        | 删除按钮；点击封面打开视频页             |
| 移出稍后        | 删除图标，辅助文本为“移出稍后再看”     |

错误日志、开发者控制台、内部字段和技术文档可以保留 `keyword`、`llm`、`manual`，但面向普通用户的主界面、首次引导和 README 使用上表中的公开术语。

## 10. 后续更新说明模板

分类目录变化：

> **分类目录调整**：新增“××”分类，并调整“××”的层级。本次更新不会覆盖手动确认的视频分类。

初步分类规则变化：

> **视频分类改进**：优化初步分类规则。新同步的视频会使用新规则，手动确认的结果不会改变。

AI 分类变化：

> **AI 分类改进**：AI 现在会参考更多视频信息。已有手动确认结果不会重新处理。

更新说明必须交代：改动的是分类目录还是视频分类、是否重新处理已有视频、是否影响手动确认结果。
