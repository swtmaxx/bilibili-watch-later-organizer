# 更新计划

目标：先把发布和现有使用流程补齐，再投入数据与交互改造较大的功能。每项上线时都保持手动确认的视频分类不被自动流程覆盖。

## 近期（按顺序）

1. **Release 提供压缩包（已完成：v1.1.0）**
   - 固定发布检查清单：更新版本号、打包扩展源码、在 Release 附上 ZIP，并说明解压后如何在浏览器中重新加载。
   - 保持 ZIP 只包含加载扩展所需文件，排除 `.git`、测试和本地代理配置。

2. **Edge 浏览器语言适配（已完成：v1.1.0）**
   - 核对 Edge 的语言环境与扩展显示文案；让界面能够正确跟随浏览器语言设置，为后续英文界面预留文案结构。
   - 这一阶段只解决 Edge 兼容与语言读取，不一次性翻译全部界面。

3. **在“手动编辑分类目录”中加入自动更新入口**
   - 在分类目录编辑区域提供清晰入口，用于让 AI 生成或替换分类目录。
   - 入口和说明必须明确：它调整的是“分类目录”，不是给已有视频重新分类；替换前展示确认提示，且不覆盖手动确认的视频分类。

4. **API 自动更新频率选项**
   - 在设置中增加关闭、每 6 小时、每天、每周等频率选择，并显示上次自动更新的时间。
   - 自动更新只同步稍后再看列表和必要的视频信息；AI 批量视频分类仍需用户主动发起，避免意外调用 API 或覆盖使用预期。

5. **视频进度**
   - 先确认 B站可稳定获取的观看进度字段，再缓存视频时长、已看时长与是否看完状态。
   - 在视频卡片显示简洁进度条和时间；后续可补充“继续观看”“按未看完筛选/排序”。需要处理旧缓存补齐和接口异常时的降级显示。

6. **分类顺序拖动优化**
   - 改进分类目录的拖动手感与落点提示，支持稳定地调整同级顺序，并明确是否允许跨层移动。
   - 保存后立即反映到左侧目录、筛选和分类选择器；重点回归层级数据、滚动状态、文字选择和批量操作，避免重新渲染导致交互失效。

## 远期目标

1. **支持 YouTube 稍后再看**：抽象视频来源与同步层，再为 YouTube 单独实现授权、列表同步、进度和跳转；不与 B站数据混淆。
2. **完整英语支持**：在 Edge 语言适配基础上，完成可见界面、首次引导、错误提示和 README 的中英文文案。
3. **历史总结**：基于观看、分类和进度数据提供时间范围总结；先定义本地数据口径和隐私说明，再设计摘要形式。
4. **B站评论区地址入口**：在评论区识别或提供地址快捷入口，先评估页面结构稳定性、误触风险和隐私影响。

## 建议的版本节奏

- **1.1.0**：发布 ZIP 与 Edge 语言适配。
- **1.2.0**：分类目录自动更新入口与 API 自动更新频率。
- **1.3.0**：视频进度。
- **1.4.0**：分类顺序拖动优化。
